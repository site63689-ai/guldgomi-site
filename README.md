# Guldgomi Honey — сервер (Node.js + Express + SQLite)

Что делает сервер:

| Функция | Адрес | Примечание |
|---|---|---|
| **ИИ-ассистент поддержки** (Anthropic) | `POST /api/v1/assistant` | ключ `ANTHROPIC_API_KEY` только на сервере |
| Приём заказов, проверка цен, SQLite | `POST /api/v1/orders` | сумму считает сервер по своей базе цен |
| Онлайн-оплата BOG и TBC | создаётся внутри заказа; webhooks `/api/v1/webhooks/bog` и `/tbc` | банк без ключей отключается сам |
| Уведомления в Telegram | автоматически | токен бота только в `.env` |
| Отзывы и чат | `POST /api/v1/reviews`, `/api/v1/chat` | пересылаются в Telegram |
| Проверка работы | `GET /health` | |

> Статус подключения сайта: виджет ассистента в присланном `index.html` уже подключён (нужен только адрес сервера).
> Приём оплаты и заказов через этот сервер в присланной версии сайта **не подключён** — там заказы пишутся в Supabase. Серверная часть оплаты готова и протестирована, см. раздел «Что дальше».

---

## 1. Требования

- Node.js **22.13 или новее** (используется встроенный SQLite).
- Аккаунт на Render или Railway, аккаунт на GitHub.
- Ключ Anthropic API (для ассистента).

## 2. Загрузка на Render (пошагово)

1. Создайте на GitHub **новый приватный репозиторий** и загрузите в него содержимое этой папки (без `node_modules` и без `.env` — они в `.gitignore`).
2. На render.com: **New → Web Service → подключите репозиторий**.
3. Настройки:
   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/health`
4. Вкладка **Environment** — добавьте переменные (таблица в разделе 4). Обязательно `NODE_VERSION` = `22`.
5. **База данных SQLite хранится в файле.** Чтобы заказы не пропадали при перезапуске, нужен постоянный диск: Render → сервис → **Disks → Add Disk**, Mount Path `/var/data`, и переменная `DB_PATH=/var/data/shop.db`. На бесплатном тарифе постоянного диска нет и сервис «засыпает» без нагрузки — для приёма реальных платежей берите платный тариф (актуальные условия проверьте на сайте Render).
6. Нажмите **Create Web Service**. Через несколько минут Render выдаст адрес вида `https://guldgomi-server.onrender.com` — **это и есть ваш адрес сервера с готовым HTTPS**. Откройте `https://…onrender.com/health` — должно быть `{"ok":true}`.
7. Впишите этот адрес в переменные `PUBLIC_BASE_URL` (как есть) и подтвердите, что `ALLOWED_ORIGINS` / `SITE_URL` — адрес вашего сайта.

### Вариант: Railway
New Project → Deploy from GitHub → переменные во вкладке **Variables**. Для базы добавьте **Volume** (Mount path `/data`) и `DB_PATH=/data/shop.db`. Домен: Settings → Networking → **Generate Domain** (HTTPS включён).

## 3. Подключение сайта

В `index.html` найдите строку и вставьте адрес сервера (без слэша в конце):

```js
const ASSISTANT_API_URL = 'https://guldgomi-server.onrender.com';
```

Загрузите обновлённый `index.html` на хостинг сайта. **Откройте сайт по его https-адресу** — с локального файла (`file://`) браузер блокирует запросы к серверу (CORS).

## 4. Переменные окружения (файл `.env` / раздел Environment)

Шаблон — `.env.example`. Главное:

| Переменная | Что это |
|---|---|
| `PUBLIC_BASE_URL` | https-адрес этого сервера |
| `SITE_URL` | адрес вашего сайта (куда банк вернёт покупателя) |
| `ALLOWED_ORIGINS` | с каких адресов сайт может обращаться к серверу (обычно = `SITE_URL`) |
| `DB_PATH` | путь к файлу базы на постоянном диске |
| `ANTHROPIC_API_KEY` | ключ ассистента (пусто — ассистент выключен) |
| `ANTHROPIC_MODEL` | по умолчанию `claude-haiku-5-5` (быстрая и дешёвая); качественнее — `claude-sonnet-5-5` |
| `ASSISTANT_DAILY_LIMIT` / `ASSISTANT_PER_IP_DAILY` | потолок запросов к ассистенту в сутки (всего / с одного IP) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | уведомления |
| `BOG_CLIENT_ID`, `BOG_CLIENT_SECRET`, `BOG_CALLBACK_PUBLIC_KEY` | Bank of Georgia |
| `TBC_API_KEY`, `TBC_CLIENT_ID`, `TBC_CLIENT_SECRET` | TBC Bank |
| `ADMIN_TOKEN` | длинный случайный пароль для просмотра заказов через админ-API |

Пустые ключи банка = этот способ оплаты автоматически отключён.

## 5. ИИ-ассистент

**Ключ:** console.anthropic.com → API keys → Create key. Вставьте в `ANTHROPIC_API_KEY`. В консоли пополните баланс и **установите лимит расходов** — это ваша главная защита от больших счетов, а `ASSISTANT_DAILY_LIMIT` — вторая.

**База знаний** — файл `knowledge/knowledge_base.md`. Он собирается из `index.html` скриптом по **белому списку публичных полей** (контакты, доставка, оплата, товары и цены, описания). Админы, PIN-коды, журнал, чаты, заказы, отзывы, реквизиты, ключи в неё попасть не могут; это проверяют автотесты.

**После любого изменения товаров, цен или текстов доставки** обновите базу знаний:

```bash
npm install
npm run build-knowledge -- путь/к/index.html   # лучше всего — файл, скачанный кнопкой «Скачать готовый сайт»
```

затем загрузите обновлённый `knowledge/knowledge_base.md` в репозиторий — Render перезапустит сервер сам. Пока файл не обновлён, ассистент отвечает по старым данным.

**Если ассистент не знает ответа или клиент просит человека,** в виджете появляется кнопка «Позвать оператора». Она переключает клиента на страницу «Поддержка», вызывает уже существующую функцию «Позвать оператора» и подставляет вопрос в поле ввода.

## 6. Проверка и тесты

```bash
npm install
npm test        # 33 автотеста: цены, оплата BOG/TBC, подписи, ассистент, база знаний
npm start
```

Тесты не обращаются к настоящим банкам и к Anthropic: используются имитации. Поэтому **первый запуск с реальными ключами обязательно проведите вручную**: тестовый заказ «Курьеру», 2–3 вопроса ассистенту, тестовый платёж в песочнице банка.

## 7. Чек-лист безопасности

- [ ] `.env` не загружен в GitHub (он в `.gitignore`).
- [ ] На сервере и в репозитории нет ключей в открытом виде, кроме раздела Environment.
- [ ] Лимит расходов задан в консоли Anthropic.
- [ ] `ALLOWED_ORIGINS` содержит только ваш сайт.
- [ ] Callback-адреса банков указаны (BOG — сервер передаёт сам; TBC — в кабинете мерчанта).
- [ ] Если токен бота или ключ утекли — немедленно перевыпустите их (BotFather `/revoke`, консоль Anthropic).

## 8. Что дальше

Чтобы заказы и оплата шли через этот сервер, а не напрямую в Supabase, нужно перенести в `index.html` отправку заказа на `POST /api/v1/orders` (ответ содержит `redirectUrl` страницы банка) и закрыть таблицу `orders` в Supabase от анонимного доступа. Это отдельный этап — см. `AUDIT.md`.
